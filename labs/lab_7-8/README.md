# Лабораторна робота № 7–8 — DM-System

## Архітектура

Корінь репозиторію є npm monorepo. Workspaces:
- `app/packages/core` — пакет `@dm-system/core`;
- `app` — React/Vite Web-клієнт `dm-system-web`;
- `app/desktop` — Electron-клієнт `dm-system-desktop`.

Core містить спільні правила валідації товарів, замовлень і назви компанії, правила переходу статусів, пошук/фільтрацію/сортування, форматування, роботу із залишками та сервіс зберігання з Dependency Injection.

Web-адаптер зберігає локальні налаштування у `localStorage`. Electron-адаптер використовує безпечний preload bridge та файлове сховище в теці `app.getPath('userData')`. Обидві платформи створюють один `createStorageService()` з Core. У DM-System каталог, замовлення, користувачі та компанії залишаються серверними сутностями GraphQL/MongoDB; локальне сховище не дублює ці дані, а зберігає налаштування робочого простору.

## Запуск і перевірка

З кореня репозиторію:

```powershell
npm install
npm test
npm run build:web
```

Окремі тести:

```powershell
npm run test:core
npm run test:web
npm run test:desktop
```

Запуск Web:

```powershell
npm run start:web
```

Запуск Electron (піднімає Vite та Electron):

```powershell
npm run start:desktop
```

GraphQL API запускається окремо з `server-graphql` згідно з кореневим README. Для підключення до API створіть `server-graphql/.env` на основі `.env.example`; секрети не додаються до Git.

## Завдання 9 — ручна перевірка спільності Core

1. У `app/packages/core/src/constants.js` тимчасово змініть `PRODUCT_LIMITS.nameMax` зі 140 на 10.
2. Перезапустіть Web (`npm run start:web`) та Electron (`npm run start:desktop`).
3. Спробуйте створити товар із назвою довше 10 символів. Обидва клієнти мають показати повідомлення про обмеження довжини назви, оскільки їхня валідація імпортується з `@dm-system/core`.
4. Поверніть `nameMax` до 140.
5. У `app/packages/core/src/validation.js` змініть повідомлення валідації назви товару, перезапустіть обидва клієнти та перевірте, що новий текст з'явився без зміни коду клієнтів.
6. Поверніть початкове повідомлення та виконайте `npm test`.

Фактичні результати ручної перевірки та скриншоти додайте до звіту після виконання цих кроків. Автоматичні тести не замінюють ручну перевірку GUI.
