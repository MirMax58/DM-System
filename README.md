# DM-System — оновлення GraphQL + MongoDB

Це набір файлів для інтеграції реальної авторизації, реєстрації компанії, приєднання за запрошенням і роботи вебробочого простору з MongoDB через єдиний GraphQL API.

## Що реалізовано

- Реєстрація з двома сценаріями: створити компанію (роль `ADMIN`) або приєднатися за кодом запрошення (роль `DROPSHIPPER`).
- Вхід за email і паролем, хешування паролів через bcrypt, JWT-токен із серверною перевіркою користувача.
- Перевірка ролей на сервері. Frontend більше не дозволяє перемикати роль вручну.
- Ізоляція даних за `companyId`, який береться з авторизованого користувача, а не з аргументів клієнта.
- MongoDB-моделі `Company`, `User`, `Invitation`, `Product`, `Order`; позиції замовлення зберігаються як вкладені `OrderItem`.
- Одноразові запрошення з терміном дії, хешуванням коду та можливістю відкликання.
- Каталог: створення, редагування, видалення, пошук і фільтрація. Керувати каталогом може адміністратор.
- Замовлення: дропшипер створює замовлення з кількома товарами; сервер перевіряє залишки й списує їх; адміністратор керує статусами та бачить замовлення компанії.
- При скасуванні замовлення зарезервований залишок повертається. Після завершення замовлення він не повертається при видаленні запису.
- Адміністратор може переглядати користувачів, створювати/відкликати запрошення та деактивувати/активувати учасників.
- Налаштування назви компанії.
- Web UI підключений до GraphQL через Apollo Client; демонстраційні `localStorage`-дані більше не є джерелом даних робочого простору.

## Структура оновлення

- `server-graphql/` — замінити відповідні файли в наявній теці сервера та додати нові підтеки `config`, `models`, `utils`.
- `app/` — замінити відповідні файли у вебзастосунку та додати Apollo Client, Auth Context, сторінку входу/реєстрації й екран компанії.

Існуючі публічні компоненти головної сторінки, стилі робочого простору, таблиці, картки та утиліти залишаються на місці. Файли в архіві мають ті самі відносні шляхи, тому їх можна скопіювати поверх кореня репозиторію.

## Налаштування та запуск

### 1. MongoDB

Потрібен локальний MongoDB або MongoDB Atlas. Для локального сервера типовий URI:

```env
MONGODB_URI=mongodb://127.0.0.1:27017/dm-system
```

Для Atlas використай URI свого кластера й дозволь мережеве підключення з IP, з якого запускається API.

### 2. GraphQL API

```bash
cd server-graphql
```

Скопіюй `.env.example` у `.env` і задай власні значення:

```env
PORT=4001
MONGODB_URI=mongodb://127.0.0.1:27017/dm-system
JWT_SECRET=ЗГЕНЕРУЙ_ВИПАДКОВИЙ_СЕКРЕТ_МІНІМУМ_32_СИМВОЛИ
CLIENT_ORIGINS=http://localhost:5173,http://127.0.0.1:5173
JWT_EXPIRES_IN=1d
```

Потім:

```bash
npm install
npm run dev
```

API буде доступний за адресою `http://localhost:4001/`.

### 3. Web frontend

В іншому терміналі:

```bash
cd app
```

Скопіюй `.env.example` у `.env`:

```env
VITE_GRAPHQL_URL=http://localhost:4001/
```

Потім:

```bash
npm install
npm run dev
```

Відкрий адресу Vite, зазвичай `http://localhost:5173/`.

### 4. Перший запуск

1. Відкрий `/register`.
2. Обери «Створити власну компанію».
3. Заповни ім'я, email, пароль і назву компанії. Цей користувач автоматично отримає `ADMIN`.
4. У робочому просторі відкрий «Користувачі» та створи запрошення.
5. Передай код іншій людині.
6. Вона відкриває `/register`, обирає «Приєднатися до компанії», вводить код і створює свій обліковий запис `DROPSHIPPER`.

Код запрошення показується лише один раз після створення. Якщо його втрачено, створи новий і відклич старий.

## Важливі правила безпеки

- Не додавай `.env` до Git. У репозиторій додаються лише `.env.example`.
- Не використовуй секрет із прикладу як production-секрет.
- Усі перевірки ролі та належності до компанії виконуються на сервері.
- У цій версії токен зберігається у `localStorage` для простого SPA/Bearer-сценарію. Для production варто перейти на secure, HttpOnly cookies або іншу захищену схему з урахуванням мобільного клієнта.
- Email-повідомлення не надсилаються: код запрошення передається адміністратором вручну. Інтеграція поштового сервісу не входила до зафіксованих вимог.
- Для production потрібно додати rate limiting, підтвердження email, процес відновлення пароля, журнал аудиту та HTTPS.

## Перевірка після встановлення

1. Створення компанії створює рівно одного першого адміністратора.
2. Повторна реєстрація з тим самим email відхиляється.
3. Неправильний пароль не дозволяє увійти.
4. Неправильний, використаний, прострочений або відкликаний код запрошення не дозволяє приєднатися.
5. Приєднаний користувач отримує тільки роль `DROPSHIPPER`.
6. Дропшипер не може створювати/редагувати/видаляти товари, переглядати інших користувачів або змінювати статуси замовлень.
7. Дропшипер бачить тільки власні замовлення.
8. Користувач однієї компанії не може прочитати або змінити дані іншої компанії.
9. Створення замовлення зменшує залишок; скасування повертає зарезервований залишок; завершення не повертає його.
10. Після перезапуску API дані залишаються в MongoDB.

## Межі цієї поставки

Це інтегрований вебклієнт і GraphQL backend для зафіксованих основних сценаріїв DM-System. Мобільний клієнт React Native ще не входить до цього архіву: він зможе використовувати той самий API, токен і модель ролей без створення другої системи даних.
